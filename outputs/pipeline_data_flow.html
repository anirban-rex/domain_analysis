Stage-by-stage report

01 · Input

Accept source code or existing facts

--source accepts Java source, a ZIP, or a precomputed facts JSON. JSON inputs skip source parsing; Java inputs are parsed into the same payload shape.

02 · Parse & normalize

Build the Facts model

The parser collects class/interface nodes, package and role, annotations, fields, method signatures, documentation, references, relationship annotations, and transaction annotations. Facts.from_json normalizes this payload for analysis.

03 · Evidence

Extract structural signals

Foreign-key relationships, transaction participation, and data co-access are calculated from available facts. If --repository points to a Git checkout, co-commit evidence is included as another signal.

04 · Semantics

Represent class meaning as vectors

Descriptions are assembled from class identity, package, role, annotations, fields, methods, related classes, and documentation. The default model is sentence-transformers/all-MiniLM-L6-v2. A complete, dimension-consistent embedding set already present in facts JSON is reused instead.

05 · Features

Combine signals per class

The feature matrix joins available structural signals with semantic dimensions, and tracks a mask so unavailable values are not treated as observed values. Git adds a feature only when that evidence is enabled.

06 · Similarity graph

Connect related classes

Candidate edges come from source references and each node’s nearest neighbors. Cosine similarity is calculated over jointly available features; edges below --min-cosine are discarded.

07 · Initial clusters

Detect Louvain communities

Weighted Louvain runs on the cosine graph with the selected resolution and seed. It produces numeric community labels and a modularity score; these are not automatically domain names.

08 · Candidate services

Assign classes to service anchors

Service anchors are identified from roles and names. Supporting classes are assigned using references, package proximity, name-token overlap, and embedding affinity; low-affinity and ambiguous assignments are recorded.

09 · Deliverables

Write machine-readable and human-readable results

results.json stores communities, service assignments, embedding provenance, features, masks, graph edges, and modularity. domain_report.html renders the interactive graph, cluster and service tables, and signal coverage.

Inputs, configuration, and important behavior

  • Required: a source directory/ZIP or facts JSON; an output directory (defaults to outputs).
  • Optional Git signal: pass --repository /path/to/checkout. Git co-commit analysis is added only if that path contains .git.
  • Semantic dependency: when embeddings are missing or incomplete, the default implementation imports Sentence Transformers and generates vectors. Install the project extra with python -m pip install -e '.[semantic]'. A complete supplied embedding set avoids model generation.
  • Graph tuning: --nearest-neighbors, --min-cosine, --resolution, and --seed affect graph construction and community detection.
  • Report location: the CLI prints the path of the generated domain_report.html; the JSON is written alongside it as results.json.
